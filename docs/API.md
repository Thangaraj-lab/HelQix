# Contracts and staged-build API (K2)

## Contracts

`15-sdk/platform/contracts` (`helqix-contracts`) holds the file 35 §8 types in Rust: `Value` (number + unit + origin + status, optional `mock`), `Provenance`, `Maturity`, `Transform`, `ModelOp` (10 ops), `Binding`, `BuildEvent`, `Issue`, `Question`, `ModelRevision`, `RunFrame`, `Source`. JSON uses the TypeScript spelling (`part.setParam`, `materialId`, `ai_hypothesis`).

- JSON Schema files: `15-sdk/platform/contracts/schema/*.schema.json`, generated by `cargo run -p helqix-contracts --features schema --bin helqix-contracts-schema -- 15-sdk/platform/contracts/schema`. A test fails if they drift from the code.
- Shared fixtures: `15-sdk/platform/contracts/fixtures/contracts.json`, with valid and invalid examples per type. Rust tests check serde accepts or rejects each; `tests_py/test_schemas.py` checks the JSON Schemas do the same (a bare number, an unknown op, a "confidence" field and a timer-style event are all rejected).
- Additions to file 35: BuildEvent kinds `op.undone` and `op.redone`; Issue, Question and Source fields spelled out; `user_stated` added to `Origin`.

The TypeScript contract package and `EngineClient`/`MockEngineClient` are UI-track work (file 37); they should be generated from these schema files.

## Engine logic

`03-engineering/crates/helqix-modelbuild`: a staged build is an op log with an undo/redo cursor. Ops that reference missing things are rejected atomically. Deterministic checks raise Issues:

| Code | Severity |
|---|---|
| `unit.mismatch` (different quantities, via the helqix-core unit registry; V to mV is fine) | blocking |
| `unit.unknown`, `port.direction`, `port.kind`, `connection.dangling`, `binding.node` | blocking |
| `part.placeholder` | warning |

Commit is refused while a blocking Issue exists. The model hash is the SHA-256 of the canonical JSON of the active ops.

## Routes (all under `Authorization: Bearer <HELQIX_API_KEY>`)

| Route | Does |
|---|---|
| `POST /v1/projects` `{"payload":{"name":"Untitled project"}}` | existing generic resource create |
| `POST /v1/projects/{id}/builds` | start an empty staged build (404 if the project does not exist) |
| `GET /v1/builds/{id}` | stored build: status, cursor, all ops, issues, revision (what a refreshed browser reloads) |
| `POST /v1/builds/{id}/ops` `{"ops":[...]}` | apply all or none (422 with the reason) |
| `POST /v1/builds/{id}/undo`, `/redo` | one op back or forward (409 if nothing to undo) |
| `POST /v1/builds/{id}/commit` | 409 with the blocking issue ids, or 201 with ModelRevision `r1`, `r2`, ... per project |
| `GET /v1/builds/{id}/events` | SSE; resumes after `Last-Event-ID` or `?after=`; ends after `committed` |
| `GET /v1/sources` | connected sources; empty with "No sources connected. Parts will be placeholders or defined from scratch." |

Staged builds, op log, events and revisions live in PostgreSQL (`migrations/0002_builds.sql`). Each mutation runs in one transaction holding the build row lock. Revision numbers are serialized per project.

Known limits: the request timeout layer also applies to SSE, so long-lived streams end at the timeout and the client resumes with `Last-Event-ID`. Starting a build from a prompt, an attachment or an import (the resolver) is not built; builds start empty and receive ops.

## Tests

- `helqix-modelbuild`: 7 tests (event order equals op order, undo removes exactly one op, restore from a stored log, atomic rejection, unit mismatch blocks commit until fixed, all checks, deterministic hash). Passed locally; 3 mutations caught.
- `helqix-contracts`: 5 tests; schema checks in Python, 11 tests, passed locally.
- `helqix-api/tests/builds_api.rs`: the full flow through the router and PostgreSQL (create project, start build, ops, blocked commit, undo, rejected op, refresh, r1, r2, SSE order and resume, sources, 404, 401). Runs in CI (`api` job), which fails if it is skipped.
- `scripts/k2_curl_demo.sh`: prints every curl command and its output against a running server; run by the CI `api` job.

On the founder's PC, Windows Smart App Control blocks some newly built test binaries (os error 4551), so the contract and API test binaries could not run locally. Linux CI is the authoritative run.
